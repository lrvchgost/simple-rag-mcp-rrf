## RAG Knowledge Base — MCP‑сервер с локальной LLM и LangGraph

### Описание

MCP‑сервер, который превращает локальную папку с документами в поисковую базу знаний. 
Разработчик подключает сервер к IDE, индексирует документы (проектная документация, внутренняя wiki, заметки) 
и задаёт вопросы — AI в IDE получает ответы, основанные на содержимом файлов. 
Внутри сервера — Corrective RAG‑пайплайн на LangGraph с локальной LLM через Ollama (без платных API).

### Результаты

- Git репозитарий с кодом и документацией
- MCP‑сервер с 4 инструментами (см. ниже)
- LangGraph‑граф с условными переходами и retry‑циклами (Corrective RAG)
- Docker Compose: сервер + Ollama + модель — запуск одной командой.
- Набор демо‑документов и тесты
- CI pipeline (lint + тесты; сборка Docker‑образа — опционально)

### Технологии

- Python, FastMCP
- LangGraph (оркестрация), LangChain (документ‑лоадеры, сплиттеры, `EnsembleRetriever` для гибридного поиска)
- Ollama + локальная маленькая LLM. (например, Phi‑3‑mini (3.8B) или Qwen2.5‑3B)
- ChromaDB — векторное хранилище (in‑process, без отдельного сервера)
- `rank_bm25` — sparse retrieval (BM25) для гибридного поиска
- Docker, Docker Compose

### Что нужно реализовать

#### MCP‑инструменты (4 инструмента)

| Инструмент | Вход | Что делает | Нужна LLM? |
|---|---|---|---|
| `index_folder` | путь к папке, glob‑паттерн | Сканирует файлы, разбивает на чанки, создаёт эмбеддинги, сохраняет в ChromaDB; перестраивает BM25-индекс в памяти | Только эмбеддинги |
| `ask_question` | строка‑вопрос | Запускает полный RAG‑пайплайн (LangGraph) | Да — локальная LLM |
| `find_relevant_docs` | запрос, top_k | Возвращает ранжированные чанки без генерации ответа (гибридный поиск: BM25 + вектор → RRF) | BM25 + эмбеддинги |
| `index_status` | — | Статистика: кол‑во файлов, чанков, время последней индексации | Нет |

> **Требование к метаданным инструментов:** у каждого инструмента должно быть содержательное поле `description`, 
по которому хост‑агент (Copilot, Claude и др.) самостоятельно определяет, когда и зачем его вызывать — без подсказки пользователя. Это проверяется в шаге 5 процесса сдачи.

#### Поддерживаемые форматы документов

- `.md`, `.txt` — текстовые файлы
- `.py`, `.js`, `.ts` — код
- `.json`, `.yaml` — структурированные данные

#### LangGraph‑граф (Corrective RAG)

Поиск — гибридный: BM25 находит документы по точному совпадению ключевых слов, векторный поиск — по смыслу запроса. 
Результаты объединяются через Reciprocal Rank Fusion (RRF): итоговый ранг документа зависит от его позиций в обоих списках. 
Это позволяет одинаково хорошо отвечать на семантические вопросы («как работает авторизация») и точечные («где используется `TOKEN_EXPIRY_HOURS`»).

```
User Query → Rewrite Query → Retrieve (hybrid: BM25 + vector → RRF)
  → Grade Chunks (relevant? yes/no)
    → enough relevant → Generate Answer → Return answer + sources
    → too few relevant → Broaden Query → Retrieve (max 2 loops)
```

Grade Chunks — это «корректирующий» шаг, который дал название паттерну. 
LLM оценивает каждый retrieved чанк: релевантен ли он вопросу (yes/no). 
Если релевантных чанков недостаточно — граф расширяет запрос и повторяет поиск (до 2 раз). 
Это защищает от случаев, когда первый запрос сформулирован слишком узко или использует другую терминологию, чем в документах.

Подход к разбивке на чанки подбирайте исходя из природы данных (текст, код), выбранный подход опишите в отчёте.

#### Дополнительные задания (необязательные)
