# 09. Два корпуса: data/proust vs demo_docs/proust

## Вопрос пользователя

«Зачем нам demo_docs/proust и data/proust одновременно?» — и сразу «а если
путь поправить?» в ответ на минус варианта с удалением.

## Разбор: дублирование — обход границы bind-mount

- **data/proust** — «родной» корпус для stdio-варианта на хосте (качается
  scripts/download_corpus.py с Gutenberg). В контейнер НЕ смонтирован.
- **demo_docs/proust** — копия того же корпуса внутри demo_docs, потому что
  compose монтирует только `./demo_docs` → `/data/docs`. Без копии
  docker-преподаватель не смог бы проиндексировать литературный корпус.
- Коммит 07ff381 был ровно про синхронизацию этих копий — то есть рассинхрон
  уже случался и руками чинился.

## Варианты и выбор

1. Оставить как есть — пути стабильны, но две копии.
2. Доп. маунт `- ./data:/data:ro`, убрать demo_docs/proust — одна копия, но
   правки README + переиндексация.
3. **Убрать data/proust из репо, скрипт качает в demo_docs/proust** — одна
   копия; минус «stdio теряет родной путь» пользователь закрыл сам: «а если
   путь поправить?» — поправить-то можно, grep показал всего ~8 мест.

Выбрали вариант 3.

## Что сделали (коммит dbfc11b, запушен)

- `scripts/download_corpus.py`: OUT_DIR → demo_docs/proust/texts (+ докстринг);
- README: все 6 упоминаний data/proust переписаны, включая сценарий проверки
  (`./demo_docs/proust` или `/data/docs/proust` в контейнере);
- `git rm -r data/proust` (−22 файла);
- проверка, что ссылок не осталось (grep — 0, кроме result.md — история
  сессии); ruff + 25 тестов; fresh-clone: корпус на месте, compose config OK.

Контейнер пересобирать не пришлось — маунт ./demo_docs тот же, индекс не
затронут.

## Итог принципа

Одна копия данных = нет синхронизаций вручную (как был 07ff381). Путь — это
просто конфиг; правится за 8 строк, если выигрыш — исчезающий класс ошибок.
