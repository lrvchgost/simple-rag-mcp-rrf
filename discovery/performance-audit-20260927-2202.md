## Ключевые выводы

1. **Искать система умеет.** Все три инцидента сессии (Одетта, «сёстры»,
   «принцесса де Лом») произошли при верно найденном контексте.
2. **Цепочка потерь сходится численно:** 4 из 9 FACT MISS = вопросы, где
   грейдер LOST gold (odette, token-expiry, token-service, verdurins-themes);
   остальные 5 — gold дошёл, но ответ тощий (coverage 0.38-0.57 при пороге 0.6).
3. **Парадокс refusal:** улучшение грейдера (unsure→true) убрало способность
   к отказу — на вне-корпусных вопросах пропускается шум → риск галлюцинаций.
   Лечение: явная ветка «все verdicts false → отказ» (уже есть в графе,
   грейдеру надо уметь её достигать).
4. **Индекс был неполон:** тех-файлы demo_docs не были проиндексированы в
   контейнере (нашлось только eval'ом); +330 стейл-чанков от stdio-запусков
   с хостовыми путями в volume.
5. **Потолок — генерация 3b на CPU.** Приоритет апгрейдов: (а) refusal-логика,
   (б) реранкер (cross-encoder) вместо 3b-грейдера, (в) крупная модель для
   generate на GPU.

## Инструментальные уроки (важно для будущих прогонов)

- Golden-факты должны быть на языке ответов (v2-урок: русский факт ↔
  английский ответ → judge «12/12 галлюцинаций» — артефакт).
- SSE-парсинг: события режутся на data-строки; r.text декодирует UTF-8 как
  latin-1; C1-символы кириллицы (\x85) ломают splitlines → рвут JSON.
  Только r.content.decode("utf-8") + склейка data-строк.
- В SSE внутренний JSON экранирован (\"status\": \"ok\") — grep-паттерн учитывать.
- ask_question на CPU: 30-70 c (до 2 циклов) → eval фоном, nohup + лог.

## Приоритет действий

**1. Refusal-логика грейдера — ВЫПОЛНЕНО:** refusal 2/2 (софт-отказ), gold-preservation 9/12, fact_ok 4/12
- Что: грейдер должен уметь выдать «все false»; граф уже умеет отвечать отказом
  («Не найдено релевантных фрагментов») — нужно только доходить до этой ветки.
- Критерий по eval: refusal 0/2 → 2/2 ✓, gold-preservation не ниже 8/12 ✓ (9/12).

**2. Реранкер (cross-encoder) вместо 3b-грейдера** — высокий эффект, средние затраты
- Что: bge-reranker-v2-m3 поверх пула top_k=20 → отбор топ-5; оценивает пару
  «вопрос+чанк» точнее 3b в JSON-режиме и без latency-домино rewrite→broaden.
- Критерий по eval: MRR 0.625 → ≥ 0.8 при recall@5 = 1.0; fact_ok 3/12 → ≥ 6/12
  (чистый контекст на входе генерации).

**3. Крупная модель для generate на GPU** — максимальный эффект по качеству,
   требует инфраструктуры (nvidia-container-toolkit + docker-compose.gpu.yml)
- Что: qwen2.5:7b/14b только для узла generate; rewrite/grade/broaden остаются
  на 3b/1.5b (GPU-проброс ускоряет и их).
- Критерий по eval: fact_ok 3/12 → ≥ 8/12, honest judge 1/14 → судить
  отдельной крупной моделью.

**4. Фоновые** — стейл-чанки в volume (330 шт., хостовые пути); parent-child
чанкинг для литературного корпуса; перезапись baseline'ов после каждого из
действий 1-3 (осознанная, не молча).
