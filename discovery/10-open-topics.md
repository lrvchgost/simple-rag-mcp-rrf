# 10. Открытые темы — что обсудить дальше

Список собран в конце сессии по вопросу «какие ещё темы из этого проекта имеет
смысл обсудить?». Упорядочено по ценности для защиты.

## Приоритет 1 — прямые апгрейды проекта

1. **Оценка качества RAG.** Весь A/B в сессии делался «на глаз» (2-3 контрольных
   вопроса). Системно: golden-набор «вопрос→эталон», recall@k по поиску,
   faithfulness ответов; eval-прогон в CI отдельно от unit-тестов (тесты без
   LLM уже есть). Это главная дыра в инженерной части.
   → **Разобрано, составлен план без реализации:** [11-eval-quality.md](11-eval-quality.md).
2. **Реранкер (cross-encoder, напр. bge-reranker).** Оценивает пару
   «вопрос+чанк» точнее, чем 3b-грейдер в JSON-режиме, и дешевле по латентности.
   Прямой апгрейд фикса грейдера из 03-grader-generator.md.
3. **Пиннинг версий.** Урок сегфолта: `ollama/ollama:latest` принёс регресс
   (01-ollama-gpu.md). Пиннить образы (например 0.5.12), модели, зависимости.

## Приоритет 2

4. **Кэширование**: эмбеддинги запросов; LLM-ответы по hash(question+контекст) —
   повторный вопрос сейчас снова ~60 c.
5. **num_ctx у ollama**: длинный контекст молча обрезается; посчитать бюджет
   токенов top_k=5 × 1000 символов + промпты.
6. **ChromaDB изнутри**: HNSW/ANN — почему поиск «ближайших» не перебор;
   метадата-фильтры; формат хранения.
7. **Альтернативы RRF**: взвешенное слияние скорсов; adaptive retrieval
   (пропускать grade при уверенном BM25-скорсе).
8. **Стриминг ответа**: ask_question отдаёт всё в конце; токены через MCP
   progress-нотификации (мостик к прогрессу индексации из 07-indexing.md).

## Приоритет 3 — фоновые

9. Сборка образа: слои, кэш, multi-stage; healthcheck; почему важен
   depends_on: service_completed_successfully (уже используется для ollama-init).
10. Безопасность локального MCP: почему отсутствие авторизации на
    localhost:8000 приемлемо, а в сети — нет.
11. Мультиязычность эмбеддера: nomic vs bge-m3; README обещает «любой язык» —
    где именно сломается.
12. Наблюдаемость: structured logging, трейсинг пайплайна (сейчас — INFO-строки).

## Контекст, который стоит держать в голове

- Железо: Intel UHD 620 + MX150 2 ГБ, 16 ГБ RAM (9 занято) → CPU-инференс —
  фундаментальное ограничение; архитектура (число LLM-вызовов) — множитель.
- Установившийся вердикт: поиск и грейдер в порядке, потолок — 3b-генерация;
  рычаг — GPU + более крупная модель только для generate.
- Итоги для сдачи: result.md в корне репо; история коммитов в git log.
