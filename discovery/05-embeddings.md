# 05. Эмбеддинги: nomic, ChromaDB и «кто создаёт смысл»

## Как разговор зашёл

Цепочка вопросов пользователя: «создание смысла — это на стороне хромадб?» →
«nomic-embed-text как он принимает, что есть связь по смыслу?» → «это LLM на
архитектуре трансформера, которая умеет возвращать вектора?». Отвечали
последовательно, поправляя модель мира.

## Поправка 1: ChromaDB смысл не создаёт

Разделение труда:
- **Ollama** (контейнер ollama) — «фабрика смысла»: `OllamaEmbedding.embed`
  (embeddings.py:41) шлёт тексты на `POST /api/embed`, получает векторы по 768
  чисел и передаёт **уже готовые** в Chroma (`ChromaVectorStorage.add`).
- **ChromaDB** — «архив и линейка»: сохранить вектор+текст+метаданные, при
  поиске посчитать косинусные углы, отдать top_k. Арифметика — да,
  понимание — нет.
- Режимы `EMBEDDING_PROVIDER` (config.py:30): `ollama` (основной) и `default`
  — встроенная ONNX-модель внутри chroma-клиента, фолбэк «без Ollama».

## Поправка 2: nomic — трансформер, но не LLM

| | qwen2.5:3b (LLM) | nomic-embed-text (эмбеддер) |
|---|---|---|
| архитектура | decoder-трансформер | encoder-трансформер (BERT-родня), ~137M |
| выход | текст, токен за токеном | один проход → вектор 768 чисел |
| обучение | next-token prediction | контрастивное |

Точнее сказать: он не «умеет возвращать вектора», а **устроен так, что его
внутреннее представление текста и есть вектор**. Не пишет ни слова.

## «Как он понимает связь по смыслу?» — никакой магии

1. Текст → токены → слои attention (каждое слово смотрит на все остальные и
   уточняет смысл в контексте) → пулинг → точка в 768-мерном пространстве.
2. Обучение **контрастивное**: миллиарды пар «запрос — релевантный текст»
   (и «нерелевантный»); функция потерь наказывает за дальние подходящие пары и
   близкие неподходящие. После этого «похоже по смыслу = рядом» — не правило,
   а **геометрия**, выученная из статистики совместной встречаемости.
3. Почему «сестра сказала» ≈ «подружка заметила»: эти слова постоянно
   встречались в одинаковых окружениях (кто-то + глагол речи + о ком-то) —
   точки легли рядом. Словаря синонимов внутри нет.
4. Даёт: устойчивость к переформулировкам/опечаткам/языку. Не даёт:
   рассуждений — это «линейка смысла», думать будет qwen.

Практическое следствие, которое обсудили: эмбеддер в ~20 раз меньше LLM, в
разы быстрее и **не может схалтурить, как генератор** — у него нет свободы
формулировать. Всё, за что мы ругали qwen (перепутать сëстер), эмбеддеру
недоступно по конструкции.

## Железное правило

Индексировать и спрашивать надо **одной эмбед-моделью** — иначе несравнимые
координаты. В README оно уже прописано: сменил EMBEDDING_PROVIDER → стирай
CHROMA_DIR и переиндексируй.
