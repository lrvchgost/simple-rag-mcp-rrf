## 1. Segfault ollama при запуске модели [system]
- **Симптом:** `500: llama-server process has terminated: signal: segmentation fault` на `qwen2.5:1.5b-instruct`.
- **Причина:** ollama 0.31.1 грузил все 29 слоёв через Vulkan-бэкенд на Intel UHD 620; llama-server падал на старте инференса. Модель целая (перекачка не помогла).
- **Решение:** откат на рабочий ollama 0.5.12 (`tar -C /usr/local -xzf ollama-0.5.12.tgz`) — в 0.5.12 Vulkan-раннера нет, падать нечему.
- **Проверка:** `ollama ps` → 9%/91% CPU/GPU (CUDA на MX150).

## 2. MCP-клиент обрывал индексацию (таймаут 20 c)
- **Симптом:** долгие вызовы index_folder умирали; в логах сервера «Request already responded to» + 404 на мёртвой сессии.
- **Причина:** `opencode.json` → `"timeout": 20000` — 20 секунд против минут индексации.
- **Решение:** таймаут 600000. (коммит 59920b2)
- **Позднее найден второй очаг:** те же 20000 в ОБЕИХ примерах конфига в README — преподаватель скопировал бы их себе. Синхронизировано с opencode.json (1b49f50).

## 3. GPU-проброс в Docker ломал чужие машины
- **Симптом (гипотетический):** `gpus: all` в docker-compose.yml валит `docker compose up` без NVIDIA/toolkit.
- **Решение:** GPU вынесен в опциональный `docker-compose.gpu.yml` (override); базовый CPU-вариант не тронут; README задокументирован. (59920b2)

## 4. Индексация «молчала» минутами
- **Симптом:** ноль обратной связи между началом и финалом index_folder.
- **Причина:** прогресса не существовало; эмбеддинги уже ходили батчами по 64 (_EMBED_BATCH), но колбэка не было.
- **Решение:** `on_progress(done, total, msg)` в indexer + async-инструмент (asyncio.to_thread) с мостом `run_coroutine_threadsafe → ctx.report_progress` (MCP progress-нотификации, без progressToken — тихий no-op). (b8170c6)
- **Проверка:** логи «эмбеддинги N/M»; полный прогон 818 чанков / 339.78 c.

## 5. Грейдер резал золотые чанки (1/5 релевантных)
- **Симптом:** тощие ответы, лишние broaden-циклы (Одетта: 1/5, 2 цикла).
- **Причина:** промпт «strict relevance grader» без критериев — малая модель читает строгость как «проще false».
- **Решение:** рубрика «relevant=true при любой полезной информации, даже частичной; false только при явно другой теме; unsure → true» (асимметрия цены ошибки). (051b677)
- **Проверка (A/B):** 1/5 → 2/5, циклы 2 → 0, источников 1 → 2.
- **Побочный эффект (осознанный):** грейдер больше не может сказать «все false» → refusal 0/2 в аудите; лечится отдельной веткой «все verdicts false → отказ».

## 6. Генератор: 3 итерации промпта — безуспешно, откат
- **Симптом:** после фикса грейдера ответ одеттовского вопроса исказился («wife of the Princesse des Laumes» при верном чанке).
- **Попытки:** анти-галлюцинация → «верно, но бесполезно»; экстракция фактов → «wife of Comtesse Swann» (неверно).
- **Вывод:** потолок 3b в синтезе, не промпта; `_GENERATE_SYSTEM` откачен к исходному, контейнер пересобран. Рабочее дерево чистое.

## 8. Тех-файлы отсутствовали в индексе контейнера

## 9. eval_retrieval: три ловушки парсинга MCP-ответов
- **Симптом:** JSONDecodeError «Unterminated string» на вопросах с кириллицей; часть ответов вообще не парсилась.
- **Причины (три слоя):** (1) SSE-событие режется на несколько `data:` строк — склейка при парсинге; (2) requests `r.text` декодирует text/event-stream как latin-1; (3) байты кириллицы → C1-символы (\x85), которые `str.splitlines()` считает переводами строк и режут JSON посередине.
- **Решение:** `r.content.decode("utf-8")` + разбор по событиям с накоплением data-строк. (44c9bb8)

## 10. eval_generation: ZeroDivision на коротком факте
- **Симптом:** краш на факте `"7"` — токен короче 2 символов отфильтровывался → пустое множество → деление на 0.
- **Решение:** числовые токены не фильтруются по длине + guard на пустое множество. (44c9bb8)

## 11. judge «12/12 галлюцинаций» — артефакт инструмента

- **Причина:** факты в golden были на русском, ответы — английские; 3b-judge не осилил кросс-языковое сопоставление цитат.

## 12. CI: wait-loop умирал на старте контейнера (ран #6, exit 56)
- **Симптом:** job eval-retrieval падала на «Wait for MCP server», `exit code 56` (curl CURLE_RECV_ERROR — uvicorn принял TCP и сбросил при старте).
- **Причины (две мины bash -e):** (1) curl без `|| true` — сетевая ошибка убивала шаг вместо ретрая; (2) `[ "$code" = "200" ] && exit 0` при не-200 возвращало 1 → `-e` убивал шаг: цикл не работал вообще.
- **Решение:** `curl --max-time 5 ... || true` + `if [ ... ]; then exit 0; fi`. (b7a3142)

## 13. CI: grep не матчил экранированный JSON в SSE
- **Симптом:** шаг Index demo docs молча не печатал статус.
- **Причина:** в SSE внутренний JSON экранирован (`\"status\": \"ok\"`), паттерн `"status": "[a-z]*"` не совпадает.
- **Решение:** `grep -o 'status[^,]*ok'`. (44c9bb8, доведён в 33e0cbc)

## 14. CI: recall 0.6 на свежем volume (ран #8)
- **Симптом:** eval падал на --fail-under 0.9; локально не воспроизводилось (локальный volume был «жирный»).
- **Причина:** 2 из 5 tech-вопросов ссылаются golden-чанками на proust-файлы (settings.yaml, themes.txt), которые CI не индексировал — корень даёт только 3 из 5.
- **Диагностика:** воспроизведение точного CI-пути локально: `compose down` + `volume rm project_chroma_data` + `up --no-deps --build` + pull + index + eval → recall 0.6 на свежем volume.
- **Решение:** в CI индексируется также верхний уровень proust (`/data/docs/proust` glob=* — 9 мелких файлов, без texts/). (33e0cbc)
- **Проверка:** локально recall 1.0, exit 0; ран #9 — все джобы success.
